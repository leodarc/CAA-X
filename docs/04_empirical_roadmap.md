## 二、短期验证（0-3个月）：认知原子存在性

### 目标
在现有LLM上通过机制可解释性工具验证认知原子的存在性。

### 实验1.1：SAE稀疏特征作为认知原子表征

**假设**: 稀疏自编码器（SAE）提取的特征具有功能专一性，可作为认知原子的神经实现。

**方法**:
1. 在 GPT-4o / Claude 3.7 / Llama 4 上训练 SAE
2. 提取 top-1000 稀疏特征
3. 人工标注特征语义（参照 Anthropic 显微镜方法）
4. 测量特征间的功能独立性（互信息 I(feature_i; feature_j) < 0.1）

**成功标准**:
- ≥60% 特征具有可解释语义标签
- 特征间平均互信息 < 0.15
- 单个特征消融导致特定功能下降 >30%

**对应预测**: Appendix B #11 (λ_meta 在 >3B 参数失效)

**所需资源**:
- 计算：8×A100 GPU，约200 GPU-hours
- 数据：OpenWebText 子集 + 自定义任务数据
- 人力：1名研究员 + 1名工程师

---

### 实验1.2：Backpack sense vector 语义验证

**假设**: Backpack Models 的 sense vector 可作为认知原子的语义级实现。

**方法**:
1. 在 Backpack Language Model 上复现 sense vector 提取
2. 将 sense vector 与 CAA-X 认知原子的持久性属性（ephemeral/durable/permanent）关联
3. 测试 sense vector 的组合性：A + B → C 的向量算术

**成功标准**:
- sense vector 的持久性分类准确率 >80%
- 组合性向量算术成功率 >70%
- 与 Roynard 四层认知基质的对应关系清晰

**对应预测**: Appendix B #1 (λ_base > θ 时全局广播)

**所需资源**:
- 计算：4×A100 GPU，约100 GPU-hours
- 代码：Backpack 官方实现

---

### 实验1.3：Codebook Features 稀疏离散验证

**假设**: Codebook Features 的离散码本条目可作为认知原子的表征级实现。

**方法**:
1. 在视觉-语言模型上训练 VQ-VAE 风格的 codebook
2. 测量 codebook entry 的激活稀疏性（<5% 同时激活）
3. 验证 codebook entry 的组合性（entry_i + entry_j → entry_k）

**成功标准**:
- 激活稀疏性 < 5%
- 组合性准确率 >65%
- 与 CAA-X 组合有效性定义（流形横截性）一致

**对应预测**: Appendix B #12 (12.5% 模块保留 < 15% λ 退化)

## 三、中期构建（3-6个月）：GWP协议引擎原型

### 目标
构建 GWP 协议引擎的可运行原型，测量 Tait et al. (2026) 的 6 个 GWT 标记满足度。

### 实验2.1：三层协议实现

**假设**: Handshake-Competition-Broadcast 三层协议可实现跨模块协调。

**方法**:
1. 实现 Handshake 层：模块能力声明与兼容性检查
2. 实现 Competition 层：基于 λ-序参量的动态优先级分配
3. 实现 Broadcast 层：全局信息分发与范围控制
4. 集成到现有 LLM Agent 框架（ReAct / Voyager）

**成功标准**:
- Handshake 兼容性检查准确率 >95%
- Competition 优先级分配与任务成功率相关性 r > 0.6
- Broadcast 延迟 < 10ms（单模块）
- 跨模块协调任务成功率提升 >20%

**对应预测**: Appendix B #17 (λ_max 模块获得广播权)

**所需资源**:
- 计算：4×A100 GPU + 推理优化
- 代码：Python + Redis/Kafka/gRPC
- 人力：2名工程师 + 1名架构师

---

### 实验2.2：Tait 标记测量

**假设**: GWP 引擎满足 Tait et al. (2026) 提出的 6 个 GWT 可测试标记。

**方法**:
1. **全局可用性**: 测量广播信息在模块间的可达率
2. **功能并发**: 测量并行模块处理时的冲突率
3. **协调选择**: 测量 Competition 层的决策一致性
4. **容量限制**: 测量系统同时处理的最大模块数
5. **持久性**: 测量全局状态在多轮交互中的稳定性
6. **目标调节仲裁**: 测量意图变化时的系统响应速度

**成功标准**:
- 6 个标记满足度 ≥ 4/6
- 与 MIRROR 框架的 41% 性能提升可比

**对应预测**: Appendix B #18 (Handshake 违规 → λ_flex 下降)

---

### 实验2.3：System-1/System-2 协调验证

**假设**: GWP 引擎可精确映射到 System-1（快速并行）和 System-2（慢速串行）的协调。

**方法**:
1. 将 Cognitive Atoms 作为 System-1 处理器（快速模式匹配）
2. 将 GWP 引擎作为 System-2 协调器（慢速全局整合）
3. 在双任务范式中测量切换成本
4. 与 Kahneman 双过程理论的行为数据对比

**成功标准**:
- System-1 任务延迟 < 50ms
- System-2 任务延迟 200-500ms
- 切换成本与认知心理学文献一致

## 四、长期集成（6-12个月）：认知流形动力学实验

### 目标
实现完整的认知流形动力学系统，验证张量动力学方程和 λ-序参量的相变预测。

### 实验3.1：认知流形几何验证

**假设**: 认知状态可表示为黎曼流形上的点，预测性张力对应向量场。

**方法**:
1. 构建高维认知状态空间（>1000维）
2. 估计 Fisher 信息矩阵作为黎曼度量
3. 计算测地线轨迹与意图偏置
4. 可视化流形结构（UMAP/t-SNE 降维）

**成功标准**:
- 流形曲率与任务难度相关性 r > 0.5
- 测地线轨迹与最优行为策略一致性 >75%
- 临界初始化区域（M_critical）的幂律统计验证

**对应预测**: Appendix B #13 (λ 与流形曲率负相关)

**所需资源**:
- 计算：16×A100 GPU，约1000 GPU-hours
- 数学：信息几何工具包

---

### 实验3.2：λ-序参量相变验证

**假设**: λ-序参量在 grokking 点发生不连续跳跃，可作为认知相变的早期预警指标。

**方法**:
1. 在模块化 LLM 上训练 grokking 任务（模加法、排列组合）
2. 实时监测 λ_K, λ_M, λ_I, λ_P, λ_S
3. 检测 grokking 点的 λ 跳跃
4. 验证 λ 跳跃早于准确率提升

**成功标准**:
- λ 跳跃先于准确率提升 ≥ 100 steps
- 跳跃幅度与泛化性能相关性 r > 0.7
- 临界初始化加速 grokking（vs 随机初始化）

**对应预测**: Appendix B #14 (λ_abd > θ → 80% 零样本推理)

---

### 实验3.3：Attention Sink 作为流形吸引子

**假设**: Attention Sink 现象可解释为认知流形上的稳定不动点。

**方法**:
1. 在 Transformer 中追踪注意力权重的演化轨迹
2. 将注意力模式投影到认知流形
3. 识别 sink 位置作为流形吸引子
4. 测量吸引子 basin 的稳定性

**成功标准**:
- Sink 位置对应流形上的局部极小值
- 吸引子 basin 大小与模型容量相关性 r > 0.6
- 正交性 token 选择（Orthorank）对应流形正交标架

## 六、前瞻性方向（24-36个月）

### 发展性AI (Developmental AI)

基于 Pachitariu et al. (Nature 2026) 的临界初始化发现，实现三阶段发展：

| 阶段 | 时间 | 目标 | 关键指标 |
|------|------|------|---------|
| **胚胎期** | 0-1月 | 临界拓扑初始化 | 幂律雪崩指数 α ≈ 1.5 |
| **幼年期** | 1-6月 | 流形结构探索 | λ 围绕 λ_critical 波动 |
| **成熟期** | 6-12月 | 任务执行与临界维持 | 实时临界性监测 |

### 多智能体社会认知

基于 MAS-GPT 和 Darwin Godel Machine，扩展 λ_S（社会协调）：
- 多智能体 GWP 协议扩展
- 合作-竞争动态相变分析
- 社会常识推理基准（False Belief Task 的 AI 版本）
